# Phase 2 Adversarial Review - Toolkit Foundation

Date: 2026-06-20

## Scope

Adversarial review of Phase 2 shared toolkit result and board-state primitives.

## Initial Findings

Architecture/code-quality reviewer findings:

- Important: `ToolkitResult` identity was collision-prone because result/layer ids used only
  packet id and the input hash omitted packet content and schema version.
- Important: `BoardState` immutability was shallow and needed documentation or a durable packet
  snapshot/digest.
- Important: `BoardState` missed units with zero models.
- Important: LOS preservation tests did not cover the refactored service/rendering path.

Spec/readiness reviewer findings:

- Important: review/work-log evidence still needed to be recorded before final phase approval.
- Important: protected-content scan in the QA doc self-matched because it scanned the QA file
  containing the regex.
- Important: `trusted` readiness was not source-backed by contract.
- Important: `BoardState` missed units with zero models.
- Minor: service-level no-mutation test was missing.

## Triage

Accepted and fixed:

- `BoardState` now stores `packet_digest`, generated by `map_packet_digest()` over
  `BOARD_STATE_SCHEMA_VERSION` and `MapPacket.model_dump_json()`.
- LOS toolkit input hashes now include `LOS_CHECKER_TOOLKIT_SCHEMA_VERSION`, tool id, packet
  digest, clamped center, and base size.
- `result_id` and LOS overlay `layer_id` include an input-hash suffix.
- Phase 2 spec documents `BoardState` as a shallow immutable wrapper over a live `MapPacket` plus
  a content digest.
- `BoardState` now emits `missing-unit-models` when a unit has no models.
- Tests now cover empty-unit warnings and packet digest changes.
- Tests now cover LOS service identity changes for moved inputs and same-id packet content
  changes.
- Tests now assert `los_checker_state().map_svg` matches the legacy direct LOS rendering path.
- Tests now assert `los_checker_toolkit_result()` does not mutate `MapPacket`.
- `ToolkitResult` now rejects `trusted` results without source refs or a passed validation record.
- Phase 2 QA protected-content scan now targets Phase 2 implementation, tests, review, spec, plan,
  and work-log files while excluding the QA file containing the regex.

## Re-Review Status

- 2026-06-20: architecture/code-quality re-review approved with no critical, important, or minor
  findings after identity, shallow-wrapper, empty-unit, and service-regression fixes.
- 2026-06-20: spec/readiness re-review approved with no code/spec/QA blockers after trusted-result,
  protected-scan, empty-unit, no-mutation, and evidence-recording fixes.

## Final Status

Approved.
